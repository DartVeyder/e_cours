# Workspace Guidelines & Rules (E-Cours)

## 1. Git Workflow & Commit Rules

> [!IMPORTANT]
> **Обов'язкове підтвердження перед створенням коміту (Mandatory Approval for Git Commits)**:
> - **ЗАБОРОНЕНО** виконувати `git commit` або `git push` автоматично без явного підтвердження користувача.
> - Після завершення та тестування змін агент зобов'язаний:
>   1. Показати список змінених файлів (`git status`).
>   2. Запропонувати чітке повідомлення для коміту англійською мовою (Conventional Commits: `feat(...)`, `fix(...)`, `refactor(...)`, `docs(...)`).
>   3. **Запитати підтвердження у користувача** (наприклад: *«Чи підтверджуєте створення коміту з цим повідомленням?»*).
>   4. Виконувати `git commit` тільки після отримання згоди користувача.

---

## 2. Мова комунікації та код (Language & Conventions)

- **Спілкування з користувачем**: українською мовою.
- **Повідомлення комітів (Git commit messages)**: англійською мовою.
- **Коментарі до коду та документація методів**: українською або англійською, залежно від контексту файлу.

---

## 3. Якість коду та перевірка (Verification)

- Перед тим як пропонувати коміт, обов'язково запустити набір автоматизованих тестів:
  ```powershell
  php artisan test
  ```
- Всі тести мають проходити успішно (0 помилок).
